# GM Engine

This folder is the engine: the rules, writing rules, procedures, templates, and scripts that every narrative uses. No narrative is played from here, and nothing from a narrative is ever stored here. `README.md` describes the whole thing; `ENGINE.md` is the manual the GM follows.

**If the user asks for a new narrative:** the play window (`Play.cmd`) is the usual way. Otherwise follow `Procedures/New Narrative.md`, step 1: ask for its name and where it should live, run `python engine/gm.py new-narrative "<Name>" --at "<folder>"`, and tell them to open that folder to set it up and play.

**The world belongs to the GM.** In a narrative, the GM builds the world from a five-question premise and the user discovers it by playing. Nothing in the engine, the templates, or the play window may show the user the world docs.

**Every narrative is a campaign.** The GM prepares a goal for the character to work toward, an opposition, and a hook written for the character the player made (`GM Only/State/Campaign.md`, from `Templates/`), builds the world around it, and opens every session itself; the first session's opening is the hook. It's a goal, never a script: side quests and detours are play, and the GM never decides how the campaign comes out.

**If the user is working on the engine itself:**
- A change to how the game works goes in `Rules/Core Rules.md`. The tables in `engine/dice.py` (outcome margins, fate odds, how damage is halved and doubled) have to match it.
- A change to how the GM behaves goes in `Rules/GM Rules.md` or the procedure it belongs to. How the campaign is run is GM Rules, "The campaign"; how it's prepared and how the hook is written is `Procedures/New Narrative.md`, steps 3 and 6; how a session is opened is `Procedures/Play.md`, "Opening a session." Between sessions the play window offers Begin (which sends `{new session}`) and holds back actions, so the GM always goes first.
- A writing rule goes in `Writing/Craft Rules.md`, in the house format (the rule in bold, exceptions, an example), with its reason in `Writing/Craft Rules History.md`. Rules come from what the user flags, never from outside benchmarks.
- The play window is `engine/gui.py` (a local server that runs Claude Code headless in the narrative's folder) and `engine/gui/app.html` (the page). It reads only player-safe files; never make it show anything from `GM Only/`. Project settings are ignored in headless runs of an untrusted folder, so the permissions the GM needs are passed as flags in `claude_command`. Every time it opens, it looks for Claude Code and Codex and asks each whether it's signed in (`claude_state` in `gui.py`, `codex_state` in `art.py`, `checkPrograms` in the page), and says which is missing or signed out: Claude Code is required, Codex only paints the pictures. The GM Model setting offers the models in `MODELS` in `gui.py` (Opus and Sonnet, by family name; Haiku is left out on purpose, as too light for the engine) and passes the chosen one in `claude_command`. What the GM is told about the window is `WINDOW_NOTE`. A conversation's first message carries the GM's startup reading (`brief` in `engine/session.py`), so the GM doesn't open each file itself: its lists have to match `Procedures/Play.md`, "Starting a conversation," and it goes only to Claude Code, never to the page or the channel.
- The play window's music is in `Audio/BGM` and is played by the page ("The main menu's music" in `app.html`), served by `/bgm` in `gui.py`. The menu has its tracks (`MENU_TRACKS`); `WORLD_BGM` loops while the GM is building a world (busy, and the narrative not yet set up) and fades out and stops when the GM is done (`playWorldMusic`, `stopWorldMusic`). Both follow the Settings volume; the Menu BGM choice is the menu's only.
- The New Narrative window is a step-at-a-time screen in the same style as the character creator (`app.html`, "a new narrative"): one question to a step (`NEW_STEPS`, with each step's page in `NEW_PAGES`), examples as buttons that fill the answer in, a "Leave it to the GM" button on the steps the GM can decide (what's in the world, story, themes, title), a step for what the player wants the world to have in it (sent as "In the world"), a box on the content step for other content the player names, and a last step that shows everything chosen, where Create the world is. What it sends (`createNarrative`) has to stay what `Procedures/New Narrative.md`, steps 1 and 2, expect.
- The character creator is part of the play window (`app.html`, "making the character"): a step-by-step screen in place of the story, shown while the sheet has a `## Character creation` section. The GM writes that section with the world's choices (`Procedures/New Narrative.md`, step 4); the choices that are the same in every world (gender, looks, nature, the attribute spread) are lists in the page, and the spread and rank counts have to match `Rules/Core Rules.md` §15. What the player made goes to the GM in braces. While the world is still being built, the creator opens early on the steps that need nothing from the world (`EARLY_STEPS` in the page), so the wait is spent on the character; the rest opens when the GM is done. The line under it that says what the GM is building is `BUILDING` in `gui.py`: it names the kind of file last written, and must never carry a file's name or a word of its contents.
- The shop is part of the play window too (`app.html`, "a shop"): a button above the message box, shown while the sheet has a `## Shop` section, that opens a screen for buying and selling. The GM writes that section when the character enters a shop and deletes it when they leave (`Procedures/Play.md`, "A shop"). The page does the sums from the section's `### Coins` list; it never changes the sheet. What the player put in the basket goes to the GM as an action ending in `{trade ...}`, and the GM plays it as a beat and settles the sheet. What a keeper pays for things is `Rules/Core Rules.md` §14.
- Pictures are `engine/art.py`. The GM asks with `gm art` (which only writes to the narrative's `Art/art.json`); the play window, or `gm art run`, has Codex paint them by running the `codex` program from the VS Code extension headless, read-only, and copying the result out of `~/.codex/generated_images`. Art is player-facing: it shows only what the character has seen.
- Saved games are `engine/saves.py`: each save is a commit in the narrative's own local Git repository (no remote, ever), carrying the session, character name, and level that the window's Load list shows. A load saves the current state first and then restores the chosen save's files with `git read-tree`. The player never sees Git.
- The engine's version is the one line in `VERSION` (now `Alpha 0.0.1`). The play window reads it for the corner of the main menu and for About, so a new version is a change to that file only.
- A feature to add or expand later goes in `ROADMAP.md`, under the section it belongs to. When one is built, delete its entry.
- A change to a template changes only narratives made afterward. Say so, and offer to apply it to existing ones if the user names them.
- The engine was forked from the Living World Engine (`C:/Users/grant/Living World Engine`). The two are separate: nothing here reads from it, and changes here don't go back to it.
