# GM Engine

This folder is the engine: the rules, writing rules, procedures, templates, and scripts that every narrative uses. No narrative is played from here, and nothing from a narrative is ever stored here. `README.md` describes the whole thing; `ENGINE.md` is the manual the GM follows.

**If the user asks for a new narrative:** the play window (`Play.cmd`) is the usual way. Otherwise follow `Procedures/New Narrative.md`, step 1: ask for its name and where it should live, run `python engine/gm.py new-narrative "<Name>" --at "<folder>"`, and tell them to open that folder to set it up and play.

**The world belongs to the GM.** In a narrative, the GM builds the world from a five-question premise and the user discovers it by playing. Nothing in the engine, the templates, or the play window may show the user the world docs.

**Every narrative is a campaign.** The GM prepares a goal for the character to work toward, an opposition, and a hook written for the character the player made (`GM Only/State/Campaign.md`, from `Templates/`), builds the world around it, and opens every session itself; the first session's opening is the hook. It's a goal, never a script: side quests and detours are play, and the GM never decides how the campaign comes out.

**The studio.** The engine is made by Gravelight Studios. The studio's team and its working files are kept outside this repository, so a downloaded copy has none.

**If the user is working on the engine itself:**
- A change to how the game works goes in `Rules/Core Rules.md`. The tables in `engine/dice.py` (outcome margins, fate odds, how damage is halved and doubled) have to match it, and so do the numbers at the top of `engine/carry.py` (§14, "Carrying").
- What a character carries is counted in `engine/carry.py`, and nowhere else: one reading of the sheet's gear lines for `gm carry` (which prints it for the GM) and for the play window (`/api/state` sends it with the sheet's text, and `/api/carry` answers what it would be after moves or with a shop's basket; neither writes anything). It takes text and gives back plain data: it opens no file and imports nothing of the engine's. A thing's size is only what the sheet marks (`(small)`, `(bulky)`, `(armload)`), never guessed. A sheet with no `(pack N)` was made before the rule: it isn't counted, the window draws it as it always did, and nothing migrates it. How the GM writes the lines is `Procedures/Play.md`, "Gear lines." `tests/test_carry.py` (`python -m unittest discover tests`) holds the counts, and fails when `carry.py` and Core Rules §14 stop agreeing.
- A change to how the GM behaves goes in `Rules/GM Rules.md` or the procedure it belongs to. How the campaign is run is GM Rules, "The campaign"; how it's prepared and how the hook is written is `Procedures/New Narrative.md`, steps 3 and 6; how a session is opened is `Procedures/Play.md`, "Opening a session." Between sessions the play window offers Begin (which sends `{new session}`) and holds back actions, so the GM always goes first.
- A writing rule goes in `Writing/Craft Rules.md`, in the house format (the rule in bold, exceptions, an example), with its reason in `Writing/Craft Rules History.md`. Rules come from what the user flags, never from outside benchmarks.
- The play window is `engine/gui.py` (a local server that runs Claude Code headless in the narrative's folder) and `engine/gui/app.html` (the page). It reads only player-safe files; never make it show anything from `GM Only/`. Project settings are ignored in headless runs of an untrusted folder, so the permissions the GM needs are passed as flags in `claude_command`. Every time it opens, it looks for Claude Code and Codex and asks each whether it's signed in (`claude_state` in `gui.py`, `codex_state` in `art.py`, `checkPrograms` in the page), and says which is missing or signed out: Claude Code is required, Codex only paints the pictures. The GM Model setting offers the models in `MODELS` in `gui.py` (Opus and Sonnet, by family name; Haiku is left out on purpose, as too light for the engine) and passes the chosen one in `claude_command`. What the GM is told about the window is `WINDOW_NOTE`. A conversation's first message carries the GM's startup reading (`brief` in `engine/session.py`), so the GM doesn't open each file itself: its lists have to match `Procedures/Play.md`, "Starting a conversation," and it goes only to Claude Code, never to the page or the channel.
- The main menu is the home screen in `app.html` ("home: the title screen" in the stylesheet, "the home screen's room" and "the main menu" in the script): a room built of layers (a drawn vault, or the painted one in `Art/Menu/Menu Backdrop.png` if there is one, served by `/backdrop`; shafts of light; a floor with a ring; dust) around a gold-and-obsidian d20 drawn with three.js (`buildDie`; `engine/gui/three.min.js`, served by `/three.js`), with the wire die in its place on a machine without WebGL. The die is the menu's cursor: each entry owns a face (its `data-face`: Continue 20, New Narrative 17, Narratives 12, Settings 8, About 5, Exit 1), and one focus (`focusEntry`), moved by the pointer or the keys, turns the die to show it. Choosing an entry rolls it (`rollDie`), and the two that leave the home screen wait a third of a second for the roll. `dieSpot` is the one place the die's position and size are worked out; the intro drops the die there. Everything is sized in `--u`, a 1920×1080 pixel scaled to the window. Its type is Cinzel and Cormorant Garamond, in `engine/gui/fonts` and served by `/font` (`--display` and `--text`; only the home screen uses them so far), and its colours are the `--m-` names in `:root`. The menu's sounds are made by the page (`SFX`: tick, clack, back), follow the Settings volume, and can each be replaced by a recorded one in `SFX_FILES`. It shows only what `/api/home` sends, which comes from `narrative.json` and `Character Sheet.md`.
- The menu's windows (Settings, Narratives, New Narrative, About) open in the Plate (`app.html`, "the plate" in the stylesheet and in the script): each is a `.sheet` holding a `.plate` with a head, a body and a foot, and the shared parts (the row and its gold bar, tablets, the slider, chips, cards, fields, `.pbtn` buttons, key hints from `keyHints`, the scrollbar) are defined once there. A window is opened and closed by its `hidden` attribute, from anywhere; `syncSheets` watches the attribute and does the rest: `#home.sheeted` sends the menu aside, `#sheetscrim` darkens the room (nothing is blurred), the die goes to the stage on the left (`stage.mode` and `dieSpot`; `spot` follows on a spring in `moveSpot`, and the layers in `DRIFT` are shifted and scaled to it), turns to the window's face and holds it, the window's name goes under it (`SHEETS`), Tab is kept inside, and it is all put back on closing. Esc steps out of whatever is innermost (`sheetBack`), and a click beside the plate does nothing. Settings opened over a narrative has no room behind it (`adrift`). A window too narrow for the stage (under 1100 across, or 4:3) leaves the die at home. A new window needs its markup and a line in `SHEETS`. Its sizes are in `--u` with a 13px floor, and its colours are the `--p-` names in `:root`. `?sheet=settings` (or `narratives`, `new`, `about`; `&step=5`) on the page's address opens one with the intro skipped, for looking at; nothing asks for it. The steps down a window's left with a page beside them (`.split`, `.rail`, `.steps`, `.pagebody`, `.nn-page`, placed by `placeRail`) are shared by New Narrative and the character creator. Play's windows are on the Plate too (below).
- The window opens on the splash and the intro (`app.html`, "the splash" and "the intro"). The splash is the studio's mark, 3.8 seconds the first time and 2.2 after; under it the room is made ready (`sceneReady`, never waited for past four seconds), and in its last beat of black the intro's heaviest frames are drawn once where they can't be seen (`warmUp`). The intro has no picture of its own: it is the home screen's room, performed. A director works out a few numbers for each frame from the time alone (`CUTS` for when things happen, `score` for the keyframes, `direct`), and the home's own layers wear them (`dress`, and `drawBackdrop`): the camera is a transform on `#scene`, which holds everything behind the scrim, and the menu is outside it. The die is thrown, bounces, and is left to the menu's own spring to show the first entry's face (`act`), so the intro's last frame is the home screen and nothing is handed over; `endIntro` takes off everything the intro put on. A key or a click skips it with a 0.4 second glide (`skipIntro`) and is never also a menu action. `introAt(t)`, or `?introAt=t` on the page's address (`&cut=short` for the short one), holds one frame for looking at. Which one plays is `OPENING`: the whole of it the first time and the short one after, or the Intro setting (`prefs.intro`: auto, full, short, off; `prefs.introSeen` is set once three seconds of the whole one have played); nothing when the window opens straight into a narrative (`START`); and only the mark, held still, under `prefers-reduced-motion`. The prefs come with the page (`__GM_PREFS__` in `gui.py`), so it knows how to open before it asks for anything. Its sounds are in `SFX` with the menu's (sting, room, shaft, spin, impact, bounce, settle) and can be replaced the same way; the strike has to stay under −12 dBFS at full volume.
- The play window's music is in `Audio/BGM` and is played by the page ("The main menu's music" in `app.html`), served by `/bgm` in `gui.py`. The menu has its tracks (`MENU_TRACKS`); when the window opens, the menu's music comes in over three seconds from the moment the intro's die lands; `WORLD_BGM` loops while the GM is building a world (busy, and the narrative not yet set up) and fades out and stops when the GM is done (`playWorldMusic`, `stopWorldMusic`). Both follow the Settings volume; the Menu BGM choice is the menu's only. `Audio/BGM/LICENSES.txt` says where each track came from and on what terms, one entry per file, headed by the file's exact name; a track added to the folder gets its entry there. `/bgm` does not serve it.
- The New Narrative window is a step-at-a-time screen on the Plate (`app.html`, "a new narrative"), with the steps listed down its left in four chapters (`NEW_CHAPTERS`), each with what was answered beside it (`nnAnswer`), and the die showing the step's number, 20 on the last: one question to a step (`NEW_STEPS`, with each step's page in `NEW_PAGES`), genre and tone as a step each, with buttons for the common ones, which can be combined, and a box for anything else (sent as "Genre" and "Tone"), examples as buttons that fill the answer in, a "Leave it to the GM" button on the steps the GM can decide (tone, what's in the world, story, themes, title), a step for the world's size (`SIZES`: small, medium, or large, sent as "Size"; when the genre says space opera the step shows `SPACE_SIZES` instead, counted in worlds and systems, with a fourth, a whole galaxy, that carries a warning and is confirmed in `suredialog` before the player can go on; what each has the GM build is `Procedures/New Narrative.md`, step 3, "How much to build"), a step for what the player wants the world to have in it (sent as "In the world"), a box on the content step for other content the player names, and a last step that shows everything chosen, where Begin building is. Esc goes back a step, and Cancel asks before it throws answers away (`nnCancel`). What it sends (`createNarrative`) has to stay what `Procedures/New Narrative.md`, steps 1 and 2, expect.
- Before the first words of the first session, the player is in the vault; the game screen is for play. A narrative keeps the home screen's room, behind a window on the Plate (`#makedialog`, with its own line in `SHEETS`), while it isn't set up, or no session has been opened, or the first is open with nothing written yet (`inVault`), and `#game` stays hidden. Once it's set up, the creator's window shows one last page, the threshold (`game.page === "threshold"`, `drawThreshold`): the character's name, the die on its 20, and Begin, which sends `{new session}` and holds the page while the GM sets the scene. `apply` calls `setVault` when a narrative's first state arrives and again when the first of the story is on the page: the plate sinks, the die is thrown, the room goes to black (`#veil`), and the game screen comes up out of it with the opening already on it. That happens once for an opened narrative (`game.left`); only a load puts the window back in the vault. "In the vault" is its own value beside `set_up`: world music and the server's `building()` stay on `set_up`, so the opening being written is a beat, not a build. `openGame` only starts the narrative; what the window shows waits for that first state, and a narrative in play comes up out of black too. Opened straight into a narrative (`START`), the window is black until it is ready. "◂ Main menu" leaves the vault without asking: the draft is kept and a build goes on in the server.
- The game screen (`app.html`, "game" and "the ledger" in the stylesheet) is furniture round a page, in the Plate's type and colours, with its chrome sized in `--u` and the story alone in the reader's own pixels (`--story-size`). Nothing moves behind the prose and nothing is drawn on a canvas. The lintel has Menu, the session list (`drawSessions`), the title over the page's axis, and End session, which asks in its own place (`askHere`, as Stop does). The page is the session log: a beat is appended and never redrawn (`renderStory`; it is drawn whole only when something else changed), in one of two faces the reader chooses (`prefs.face`, Garamond or Book; Settings, "Reading"; `?face=` on the page's address shows one for looking at). The desk is the message box with Send inside it, one line over it (the GM working, a session being reread, or Begin between sessions), and under it who is being spoken to, Undo, I meant and Push; speaking to the GM, the box wears braces. Push says what it costs and how much Strain is left, and warns at the last 2 (`showPush`; Core Rules §5). The ledger is the side panel: five tabs, a drawer over the page under 1180 across (`NARROW`, `showLedger`), and Stats never needs a scroll (`fitStats`). The window shows nothing of a roll, ever. Esc steps out of one thing to a press and, with nothing open, opens the game's menu (`playBack`); the screen's other keys are in one listener beside `atEase`. Play's sounds are the menu's, quieter (`sfx` takes a level): `clack` only for what goes to the GM, one `settle` as a beat arrives, and no music.
- Play's windows are plates centred over the dimmed page ("play's windows on the plate" in the stylesheet; `PLAY_PLATES`, each with `play: true` in `SHEETS`): the game's menu, Save, a passage flagged and a beat meant otherwise are small plates (`.sheet.small`); Load, Session closed, a new level and the shop are full ones. `onlyPlate` opens one in another's place, and `setHtml` keeps a tick from redrawing what hasn't changed. The game's menu (`openMenu`) has Save, Load, the last session's end, a recap, Settings, a fresh conversation, the folder, Main menu (through black, to the die on Continue's face) and Exit. A new level is built of the character creator's own classes. What any of them sends the GM is what it always sent.
- The game can't be closed while a world is being built. Exit Game and the window's own X (`closing` in `run`, in `gui.py`, which has the page call `askExit`) both go through `/api/exit`, which, with a build running (`building()` in `gui.py`) and not told to stop it, only answers that one is; the page then asks in `#exitdialog`: Stay, or Stop the build and exit, which stops the GM first. `finish()` stops a build too, so nothing ever builds unseen (a browser tab can't be kept from closing; the page has the browser ask). A beat in play is still left to finish writing.
- The character creator is that window (`app.html`, "making the character" in the script, "the character creator" in the stylesheet): a step at a time, shown while the sheet has a `## Character creation` section. The GM writes that section with the world's choices (`Procedures/New Narrative.md`, step 4); the choices that are the same in every world (gender, looks, nature, the attribute spread) are lists in the page, and the spread and rank counts have to match `Rules/Core Rules.md` §15. What the player made goes to the GM in braces (`makerLines`, `createCharacter`), and that message must not change with the look. What the window shows is `game.page`, which `apply` decides each tick and `showMake` draws: `make`, a step (`MAKER`, `drawMake`; the step is kept by its name in `game.make.at`, never its number, since the list grows when the world is ready); `handing`, the finished character held while the GM writes them in; or `side`, the GM's side, which is the conversation (`drawSide`), with Send or Stop in the foot (Stop asks first) and Settings and Fresh conversation in the head (the narrative's folder is not offered before play: it is where the world is being written). Behind it the room is drawn thirty times a second (`eased` in `startBackdrop`), since a build can last an hour or two. A tick redraws only what has changed, so it never takes the page out from under the player. While the world is still being built, the creator opens early on the steps that need nothing from the world (`EARLY_STEPS`), with the rest listed sealed (`makeRail`); when the world is ready they unseal around the player, who stays on the step and the caret they had (`worldReady`). The die shows the step's number and 20 on Review, and the character's name is under it as it's typed (`stageName`). The line under that on what the GM is building (`makeBuild`; in the foot where there is no stage) is `BUILDING` in `gui.py`: it names the kind of file last written, and must never carry a file's name or a word of its contents.
- The Inventory tab of a counted sheet is where the player packs (`app.html`, "the pack" in the stylesheet and the script). The page splits no gear line and does no sums: it draws `game.carry`. A thing opened shows each place it can go and why not the others, from one `/api/carry` answer; a move waits in `game.gear`, drawn where it would go, and rides out with the player's next action as `{gear ...}` (`gearRider`, in `send`), or on its own from the waiting bar. A new sheet lets the waiting moves go. Arms full shows on the Inventory tab's badge and on the desk (`showGear`), whichever tab is up. The shop shows each ware's size and the room left with the basket in it (`shopRoom`). What the GM is told about `{gear ...}` is in `WINDOW_NOTE` and `Procedures/Play.md`.
- The shop is part of the play window too (`app.html`, "a shop"): a button above the message box, shown while the sheet has a `## Shop` section, that opens a plate for buying and selling: shelves on the left, the basket and its sums on the right, and the keeper's portrait when there is one. The GM writes that section when the character enters a shop and deletes it when they leave (`Procedures/Play.md`, "A shop"). The page does the sums from the section's `### Coins` list; it never changes the sheet. What the player put in the basket goes to the GM as an action ending in `{trade ...}`, and the GM plays it as a beat and settles the sheet. What a keeper pays for things is `Rules/Core Rules.md` §14.
- Pictures are `engine/art.py`. The GM asks with `gm art` (which only writes to the narrative's `Art/art.json`); the play window, or `gm art run`, has Codex paint them by running the `codex` program from the VS Code extension headless, read-only, and copying the result out of `~/.codex/generated_images`. Art is player-facing: it shows only what the character has seen.
- Saved games are `engine/saves.py`: each save is a commit in the narrative's own local Git repository (no remote, ever), carrying the session, character name, and level that the window's Load list shows. A load saves the current state first and then restores the chosen save's files with `git read-tree`. The player never sees Git.
- The engine's version is the one line in `VERSION` (now `Alpha 0.0.1`). The play window reads it for the corner of the main menu and for About, so a new version is a change to that file only.
- A feature to add or expand later goes in `ROADMAP.md`, under the section it belongs to. When one is built, delete its entry.
- A change to a template changes only narratives made afterward. Say so, and offer to apply it to existing ones if the user names them.
- The engine was forked from the Living World Engine (`C:/Users/grant/Living World Engine`). The two are separate: nothing here reads from it, and changes here don't go back to it.
